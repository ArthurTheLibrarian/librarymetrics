**Final R Project: librarymetrics**

This is the Markdown file for the librarymetrics package that I, *Arthur Christoffersen*, am creating for my R Programming Course. This package is meant to enable the quick production of graphs and data analysis from a series of CSV files, which hold the daily data regarding a hypothetical library's usage metrics.

As a quick note, this package does rely on the data.table package so make sure to install it and add it to the library before making use of this package. You can do so by:

install.packages("data.table")\
library(data.table)

At the moment, there are four functions in this project, though there are likely to be more added in the future as this package develops. These are:

-   barwvis

-   createddf

-   dailymetrics

-   readData

The barwvis function is used to return a graph showing the total visitors of the library for each day. The function takes the list generated by the readData function and generates a bargraph for the relevant data. Similarly, the dailymetrics function takes the list generated by the readData function along with the indicated day, which is represented numerically and is reflected in the structure of the list. This function returns a series of strings that indicate various metrics within a single day. If this package were to be developed further beyond the length of the project, more metrics could be indicated or graphs made, but for a prototype, this is good enough.

The createddf function is an important function that is used in the readData function. createddf is simply used to convert a list item into a singular dataframe. This function is necessary because the readData function as it is creates an initial list without converting the CSV files into dataframes. Combined with the createddf function, this converts each list element into a dataframe and then recreates the list so that it is a list composed of separate dataframes, which allows us to easily work with the data and create the necessary graphs and metrics using barwvis and createddf.

In order to properly use this package, it is necessary to have the sampledata folder provided to show the general structure of the CSV files. This is provided in the package and you can refer to the path using:

upath \<- system.file("sampledata", package="librarymetrics")

Much of this package will be incompatible if the CSV files do not match the general structure of the sample data. To use this package, begin by creating a list element using the readData function. Also, the folder you're using for the data should only have CSV files within and should follow a similar layout and nomenclature. The nomenclature is YYMMDD.csv, thus the data for January 1, 2025 would be 250101.csv.

Place the sampledata folder in the working directory of your computer and make sure to put the name of the "samplefolder" in quotes when using the readData function, like so:

s1 \<- readData("sampledata")

This will create the list that you'll use for the later functions. You can look at the metrics of a particular day by using the dailymetrics function. The first element in the function will be the list, and the second will be the day in the list, represented numerically, like so:

dailymetrics(s1, 1)

For the barwvis function, simply inserting the list in the function is enough, like so:

barwvis(s1)

This will return a bar graph showing the total visitors by day. As the package is developed, more types of graphs and metrics will be available. For this particular version, this is the extent of the analysis done.

While the functions for returning the metrics and graphs were rather simple to construct, the readData function was the most difficult and time consuming function to create for this package despite its relative shortness. My greatest issue for this function was its tendency to create a list of the CSV files without converting the individual elements to data.frames. The conversion was necessary because having the data of each day as a data.frame was what made manipulating the data so easy. I found out about an hour in that I could convert each element into a data.frame, so the question then was how to convert the list to a dataframe while still maintaining its integrity as a list so that there was only one variable I had to reference for all the data. In the end, a simple for loop in the readData function was able to convert the list into a list of data.frames.

```{r}
    for(i in 1:length(filenames)){
        finallist[[i]] <- createddf(temp1, i)
    }
```

Besides that issue, I also struggled with finding a way to import the potentially variable amount of csv files. I originally had the idea to query the user for how many days and then working backwards from the current date, but I decided eventually that it was overly complicated. Instead, the user can place all the data they want in a single folder and have the program just import all the files in the folder. Making it uniform in nomenclature also allows the data to be collected in a way that preserves the chronological progression of the data. To that end, the data.table package was a godsend in making the labor of importing the data so easy, saving me many lines of code and headache with the fread function.

```{r}
    filenames <- list.files(path=datapath, full.names=TRUE)
    temp1 <- array(lapply(filenames, fread))
```
